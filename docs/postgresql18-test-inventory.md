# PostgreSQL 18 Compatibility Test Inventory

**Draft refreshed 2026-10-14.** This is the issue-to-test planning ledger for the PostgreSQL 18.6 compatibility backfill. It records tests found in the current checkout, remaining focused cases, and the dependencies that control their order. It is not a test result or a claim of parity.

The GitHub milestone snapshot has **69 open owners and 20 closed owners**. All 69 open owners are listed below. Test-file presence includes uncommitted files in the current checkout and does not prove that an assertion matches PostgreSQL 18.6 or fails in Cassie.

## How to use this ledger

- **Found** means matching test code exists in the checkout. **Partial** means the listed acceptance cases still need focused assertions. **Gate** means the issue needs corpus, client, workload, resource, or release evidence in addition to Rust tests.
- Proposed names are planning names. Keep each test focused, named with the should_ prefix, and structured with Arrange / Act / Assert.
- Use pinned PostgreSQL 18.6 as the behavior oracle. A rejection test must check the intended error path and SQLSTATE over pgwire; checking only that it errors is not sufficient.
- Prefer executed values and descriptors over parse-only checks. Use real table rows, joins, grouping, ordering, indexes, parameters, text and binary wire paths, transactions, rollback, persistence, and restart where the owner requires them.
- Presence in this ledger is not RED evidence. Record the exact PostgreSQL result and Cassie result before marking a case qualified.
- Keep this task test-only. Do not add runtime fixes as part of an inventory row.
