# `pg_attribute.attidentity` for supported identity columns

PostgreSQL 18.6 reports `a` for GENERATED ALWAYS AS IDENTITY and `d` for
GENERATED BY DEFAULT AS IDENTITY; SERIAL and ordinary columns have the empty
internal `char` value. ALTER SET GENERATED changes the reported mode and DROP
IDENTITY clears it. The direct column's wire OID is 18. PostgreSQL's binary
`charsend` encodes these three values as bytes 61, 64 and 00 respectively.

For ordinary table columns, use the already-persisted `FieldConstraint.identity`
to report the same codes; views and materialized outputs keep the existing empty
value. Do not infer or add generated-column support. A direct `pg_attribute`
column or wildcard-only direct projection reports OID 18 while preserving TEXT
as the SQL carrier. The empty internal char is encoded as one zero byte for
binary format; invalid longer strings remain errors. Explicit casts retain their
own descriptors. Joined/nested sources and mixed wildcard/expression projections
retain their previous descriptor behavior so an unrelated column or duplicate
alias is not retyped. This is a partial catalog descriptor correction, not
full pg_attribute or generated-column qualification.

Table creation, mode change, identity drop, SERIAL/plain, local restart and
wire/binary probes are authored but unexecuted. No format, Midge API, or public
storage migration is introduced. The full consolidated validation and remaining
#817 behavior remain open.
